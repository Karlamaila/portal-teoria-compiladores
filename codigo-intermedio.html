Código intermedio y código final

Qué es una representación intermedia, qué formas puede tomar y cómo se llega al código máquina.

Entre el programa fuente y el código máquina hay una representación intermedia (IR). Existe para separar lo que depende del lenguaje de lo que depende de la máquina, y para dar un lugar cómodo donde optimizar.

Ideas clave

  • Con una IR común se escriben N front-ends y M back-ends en lugar de N×M compiladores completos.
  • Hay varias formas de IR: tres direcciones, postfija, AST/DAG, SSA, bytecode y LLVM IR.
  • El código final exige elegir instrucciones, asignar registros y, luego, enlazar y cargar.

Qué es la representación intermedia y por qué existe

La representación intermedia (IR) es una forma del programa que no es ni el lenguaje fuente ni el código máquina. Es un punto de encuentro: el front-end la produce y el back-end la consume.

Tiene dos ventajas principales. La primera es la portabilidad: para llevar un lenguaje a una nueva arquitectura solo hay que escribir un back-end nuevo. La segunda es la reutilización: las optimizaciones se escriben una vez sobre la IR y sirven para todos los lenguajes y máquinas.

Con IR comúnN + M3 front-ends + 4 back-ends = 7 piezas

Introducción a SSA

En SSA cada asignación crea una variable nueva (x1, x2…). Cuando dos caminos del programa se juntan, φ elige según de dónde se venga. Esto hace evidente de dónde sale cada valor y simplifica muchas optimizaciones.

Programa original
x = 1
si (c) entonces
    x = 2
fin
y = x + 1
En forma SSA
x1 = 1
si (c) entonces
    x2 = 2
fin
x3 = φ(x1, x2)
y1 = x3 + 1

Ejemplo paso a paso: de una expresión a tres direcciones

Tomemos la sentencia x = (a + b) * (c - d).

  1. Se recorre el AST de abajo hacia arriba: primero las sumas y restas de los paréntesis.
  2. Cada resultado parcial se guarda en un temporal nuevo (t1, t2…).
  3. El último temporal se asigna a la variable destino.
Código de tres direcciones
t1 = a + b
t2 = c - d
t3 = t1 * t2
x  = t3
Las mismas instrucciones como cuádruplas.

En tripletas se omite el campo resultado y se usa el número de la instrucción: la 3 sería (3) * (1) (2). En notación postfija la expresión queda a b + c d - *.

Optimización: antes y después

El middle-end aplica transformaciones que no cambian el resultado del programa. Estas son cuatro de las más conocidas.

Plegado de constantes

Se calcula en compilación lo que ya se conoce.

x = 3 * 4 + y     →     x = 12 + y

Eliminación de código muerto

Se quita lo que nunca influye en el resultado.

x = a + b         →     x = c * 2
x = c * 2               imprimir(x)
imprimir(x)

Propagación de copias

Se usa el valor original en lugar de una copia.

t = x             →     y = x + 1
y = t + 1

Desenrollado de bucles

Se repite el cuerpo para evitar el costo de controlar el bucle.

para i en 0..3:   →     suma += v[0]
    suma += v[i]        suma += v[1]
                        suma += v[2]
                        suma += v[3]

Código final

El back-end convierte la IR en instrucciones de una máquina concreta. Sus tareas principales son:

  • Selección de instrucciones: elegir qué instrucciones de la arquitectura implementan cada operación de la IR.
  • Asignación de registros: decidir qué valores viven en los pocos registros físicos y cuáles se guardan temporalmente en memoria.
  • Ordenamiento de instrucciones: reordenarlas para aprovechar mejor el procesador sin cambiar el resultado.
  • Manejo de memoria: la pila guarda variables locales y datos de las llamadas a funciones; el heap guarda memoria dinámica que dura más que una llamada.
  • Ensamblado: pasar de ensamblador a código máquina binario, en un archivo objeto.

Enlazado y carga

El enlazador (linker) une los archivos objeto y las bibliotecas en un solo ejecutable, y resuelve las referencias entre ellos (por ejemplo, la llamada a una función definida en otro archivo). El cargador (loader), parte del sistema operativo, coloca ese ejecutable en memoria y lo prepara para correr.

Ejemplo ilustrativo: C → IR → ensamblador x86-64

Ejemplo simplificado

La salida exacta cambia según el compilador, su versión y el nivel de optimización. Estos fragmentos están ajustados para que sean fáciles de leer.

C
int suma(int a, int b) {
    return a + b;
}
LLVM IR
define i32 @suma(i32 %a, i32 %b) {
entry:
  %add = add nsw i32 %a, %b
  ret i32 %add
}
x86-64 (Intel)
suma:
    lea  eax, [rdi + rsi]
    ret

En la convención de llamadas de Linux x86-64, los dos primeros argumentos llegan en los registros rdi y rsi y el resultado se devuelve en eax.
