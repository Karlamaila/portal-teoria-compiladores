Fases del proceso de compilación

Las seis fases, recorridas con un único ejemplo: resultado = precio * 2 + impuesto;

Compilar es transformar el programa paso a paso. Cada fase recibe una representación y entrega otra más cercana a la máquina. Aquí seguimos la misma línea de código a través de las seis fases para ver qué cambia en cada una.

Ideas clave

  • Las tres primeras fases analizan el programa; las tres últimas lo sintetizan.
  • La salida de cada fase es la entrada de la siguiente: tokens, AST, AST anotado, código de tres direcciones, código optimizado, ensamblador.
  • La tabla de símbolos y el manejo de errores participan en todas las fases.

El ejemplo que seguiremos

Usaremos una sola sentencia, escrita en un lenguaje sencillo parecido a C, en un programa donde precio, impuesto y resultado fueron declaradas como float:

Programa fuente
float precio, impuesto, resultado;
resultado = precio * 2 + impuesto;

Recorrido interactivo por las seis fases

Usa los botones, las pestañas o las flechas del teclado (izquierda y derecha, Inicio y Fin) para pasar de una fase a otra.

1. Análisis léxico

Objetivo: agrupar los caracteres en unidades con significado (tokens) y descartar espacios y comentarios. Se basa en expresiones regulares y autómatas finitos.

EntradaFlujo de caracteres del programa fuente.
SalidaSecuencia de tokens.
Errores típicosCarácter inválido (@), número mal formado (2.3.4), cadena sin cerrar.
Tokens de la sentencia
<ID, "resultado">  <ASIGNACION, "=">  <ID, "precio">  <OP_MUL, "*">
<NUM, "2">  <OP_SUMA, "+">  <ID, "impuesto">  <PUNTO_Y_COMA, ";">

2. Análisis sintáctico

Objetivo: comprobar que los tokens siguen la gramática del lenguaje y construir el árbol de sintaxis abstracta (AST). La precedencia queda reflejada en la forma del árbol.

EntradaSecuencia de tokens.
SalidaAST (o árbol de derivación).
Errores típicosFalta de ;, paréntesis sin cerrar, expresión incompleta como precio * ;.
AST
Asignación
├── resultado
└── Suma (+)
    ├── Multiplicación (*)
    │   ├── precio
    │   └── 2
    └── impuesto

3. Análisis semántico

Objetivo: verificar el significado: que las variables estén declaradas, que los tipos sean compatibles y que se respeten los ámbitos. Consulta y completa la tabla de símbolos.

EntradaAST y tabla de símbolos.
SalidaAST anotado con tipos.
Errores típicosVariable no declarada, tipos incompatibles, número incorrecto de argumentos.
AST anotado
Asignación : float
├── resultado : float
└── Suma : float
    ├── Multiplicación : float
    │   ├── precio : float
    │   └── int_a_float(2) : float     // conversión implícita
    └── impuesto : float

Como precio es float y 2 es int, el compilador inserta una conversión para que ambos operandos tengan el mismo tipo.

4. Generación de código intermedio

Objetivo: traducir el AST a una representación lineal, independiente de la máquina. Aquí se usa código de tres direcciones, con una operación y como máximo tres operandos por instrucción.

EntradaAST anotado.
SalidaCódigo de tres direcciones.
Errores típicosCasi no hay errores del programador; los fallos suelen ser defectos del propio compilador.
Código de tres direcciones
t1 = precio * 2.0
t2 = t1 + impuesto
resultado = t2

5. Optimización

Objetivo: reducir instrucciones, tiempo o memoria sin cambiar lo que hace el programa. Aquí la propagación de copias elimina el temporal t2.

EntradaCódigo intermedio.
SalidaCódigo intermedio equivalente y más eficiente.
Errores típicosAvisos de código inalcanzable o variables sin usar; un optimizador defectuoso podría alterar el comportamiento.
Antes
t1 = precio * 2.0
t2 = t1 + impuesto
resultado = t2
Después
t1 = precio * 2.0
resultado = t1 + impuesto

6. Generación de código final

Objetivo: elegir instrucciones de la máquina destino, asignar registros y producir ensamblador o código objeto. Después, el enlazador y el cargador lo convierten en un programa en ejecución.

EntradaCódigo intermedio optimizado.
SalidaEnsamblador o código máquina.
Errores típicosInstrucción no disponible en la arquitectura, falta de registros (se usa la memoria), símbolo sin definir al enlazar.
x86-64 (sintaxis Intel, simplificado)
movss  xmm0, [precio]       ; cargar precio
mulss  xmm0, [dos]          ; × 2.0 (constante en memoria)
addss  xmm0, [impuesto]     ; + impuesto
movss  [resultado], xmm0    ; guardar el resultado

Es una versión simplificada: un compilador real manejaría convenciones de llamada, alineación y nombres de variables locales.

Lo que atraviesa todas las fases

Tabla de símbolos

El análisis léxico registra los identificadores; el semántico completa sus tipos; el generador de código consulta sus posiciones. En el ejemplo guarda precio, impuesto y resultado como float.

Manejo de errores

Cada fase puede detectar errores, y el compilador debe informar la línea y la causa, y seguir analizando para mostrar más de un error por ejecución cuando sea posible.
